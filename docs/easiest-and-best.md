# Easiest and best — sitting brief

Written at #95-new, 9 September 2026, for the next sitting.

The opening read is still `docs/handoff.md`. Then open this file. Do
not search old chats for the distinction below. It is here.

This sitting judges how close the app comes to Patrick’s aim: the
easiest reminder to use, and the best reminder. It does not rebuild
unless he says Go on a named piece.

## The aim

Reminders that are rock solid when you use them. Consistency beside
that. Established practice rather than a private arrangement.

On top of those, this look asks: is this the easiest reminder a
person can use, and is it the best reminder?

Judge the real path a person takes. Opening the app. Adding. Changing.
Being told. Marking done. Coming back tomorrow.

## Do not mix these two up

**Engine facts belong in the one description of each kind.** When it
fires, what Done does, whether it can be pushed back, which banner
buttons it gets: one description, and every place that acts reads
that. A leftover copy of the same fact, listed by kind name at a
second place, is a hole.

**What a kind looks like on the add-and-edit screen is ordinary
software.** Weekly showing weekday chips is Weekly. That is not a
special rule for one type of item, and it is not a hole.

**A special extra rule for one type of item is the other thing.** If
one kind cannot go through the ordinary path and needs a side path
that someone has to remember, that is the failure this project has
been taking out.

Do not treat “the screen still knows which kind it is” as the
failure. That mistake cost a sitting. Do not make it again.
